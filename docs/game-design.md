# Fowl Play：玩法框架 v0.1

本文件把已确认的方向与可试玩的默认方案分开。除“已确认”条目外，具体规则、数值与动物技能都是设计提案，后续通过试玩调整。实现顺序见 [路线图](roadmap.md)。

## 1. 游戏定位

一句话：**在有掩体和道具的农场中，操控能力各异的动物，用走位、普攻与技能赢得短局对战。**

已确认：Godot；纯 2D 素材表现 2.5D 俯视纵深；参考《荒野乱斗》的战场观察方式；左侧摇杆移动，右侧按钮点按释放；猪、马、鸡等差异化动物；农场环境与特色道具；目标渠道为 TapTap。

建议默认：Android 横屏优先，单局约 2 分钟，操作易上手，能力和命中反馈清楚。参考作品用于描述视角和操作习惯，动物造型、地图、界面、名称与资源自行设计。

三个体验重点：

- 动物差异：换一个动物，应当明显改变进攻距离、走位方式或技能时机。
- 农场互动：绕围栏、打掉干草掩体、争夺玉米，让地图参与对战。
- 操作反馈：玩家能看清技能方向、危险范围、命中与冷却，失败后知道原因。

## 2. 核心循环与游戏流程

局内循环：观察对手与地形 → 移动找位置 → 普攻试探 → 把握技能时机 → 利用掩体或道具 → 击败对手／撤退恢复 → 继续争夺。

完整流程：主菜单 → 选择动物／进入原型训练 → 加载农场 → 倒计时 → 对战 → 结果 → 再来一局／返回菜单。

M1 训练场可以直接启动；M2 才补齐菜单、对局、结算和重开。联网房间、匹配、账号属于后续阶段。

## 3. 操作方案

| 操作 | 手机 | 开发用键鼠 | 首版行为 |
| --- | --- | --- | --- |
| 移动 | 左侧固定虚拟摇杆 | WASD／方向键 | 360° 移动，松手停止；斜向不加速 |
| 普通攻击 | 右侧较大的普攻按钮 | 鼠标左键 | 点一次尝试攻击一次，受攻击间隔限制 |
| 主动技能 | 右侧一个技能按钮 | 空格 | 点按释放；冷却时显示剩余时间 |
| 瞄准 | 点按时辅助选敌 | 鼠标指向 | 移动方向与攻击方向独立 |
| 取消 | 后续拖拽瞄准时提供取消区域 | 后续 Esc／右键 | 首版点按操作不需要拖拽 |

点按辅助瞄准的默认规则：只考虑当前可见、射程内、未被障碍遮挡的敌人；优先保留仍有效的当前目标，否则选最近目标，等距按稳定实体 ID 排序。没有目标时朝最近一次有效瞄准方向攻击，尚无瞄准记录则使用朝向。自我增益技能直接对自己生效。

拖动技能按钮进行定向释放可作为后续增强，先检验纯点按是否满足手感。不要在第一版把右半屏整个变成持续瞄准摇杆。

左摇杆和右按钮必须可同时使用。每根手指独立跟踪；手指移出按钮、应用切后台或触摸取消时应正确释放状态。桌面鼠标模拟不能替代真机多指验收。

## 4. 2D 画面如何产生纵深

- 固定俯视斜角风格，地面绘在 2D 平面，动物立绘向上延伸；无需强制使用菱形等距格。
- 角色与掩体按脚底的 Y 坐标排序：靠下的物体通常遮挡靠上的物体。
- 移动碰撞使用脚底投影；受击区域独立配置，避免把整张高立绘当成地面障碍。
- 地面阴影、统一视角、围栏与干草的侧面、前后遮挡共同建立体积感。
- 装饰性跳动只抬高贴图，影子和地面位置保持可读；默认不改变命中规则，不产生跨墙能力。
- M1 先做左右朝向与翻转占位图；完整风格验证后，再决定四方向或八方向动画的成本。

UI 参考画布建议为 1280×720，适配刘海与安全区。竞技视野以统一的战斗显示范围为准，宽屏多余区域可留边或放装饰，避免屏幕更宽直接获得更远视野。具体清晰度在目标手机上确认。

## 5. 动物体系：先验证三个不同战斗定位

每只动物初期配置 **一种普通攻击＋一个主动技能**。被动、第二技能和终极技能先留在候选列表，不增加首版按钮数量。

| 动物 | 定位与主要区别 | 普通攻击提案 | 主动技能提案 | 主要弱点 | 制作阶段 |
| --- | --- | --- | --- | --- | --- |
| 鸡 | 轻快的中距离角色，首个教学动物 | 飞羽：沿瞄准方向发射直线弹体 | 扑腾疾跑：短时间提高移速 | 血量低，依赖距离和掩体 | M1–M2 |
| 猪 | 耐打、近距离施压与封路 | 拱击：前方小扇形近战 | 泥浆区：在目标地面留下短时减速区 | 移速较慢，容易被拉开距离 | M4 |
| 马 | 快速接近与直线突破 | 蹄击：前方短距离攻击 | 奔袭：沿指定方向短距离冲锋，碰到实心障碍停止 | 冲锋方向容易预判，失误后有空档 | M4 |

以上能力尚未最终定稿。鸡的增速不提供无敌、穿墙或免控；马的冲锋需要独立验证扫掠碰撞；猪的泥浆初拟影响敌人，场景天然泥地则影响所有动物。差异均用配置明确表达。

角色数值拆为生命、移速、体型、普攻参数、技能参数。动画、音效、图标和特效与逻辑分离；换动物不复制整套移动与伤害代码。

## 6. 地图与道具

首张地图“农场试验场”：一个小型围栏场地、两个出生区、中央有掩体和可争夺资源、两侧有绕行通道。先保证出生点到中心的距离接近，避免狭窄死角和无法脱离的卡位。

| 元素 | 分类 | 作用与首版规则 | 阶段 |
| --- | --- | --- | --- |
| 围栏 | 固定地形 | 阻挡角色与直线弹体；无法破坏 | M1 |
| 干草堆 | 可破坏掩体 | 阻挡角色与弹体；有生命值；破坏后移除碰撞，不掉落物品 | M2 |
| 玉米 | 自动拾取道具 | 受伤时靠近回复固定生命；满血不消耗；固定刷新点与刷新时间 | M2 |
| 泥地 | 场景区域 | 进入后减速，离开后解除；与猪技能复用状态效果机制 | M4 |
| 草丛 | 视野机制候选 | 涉及发现距离和联网可见性，先不做 | 后续候选 |
| 炸药桶／移动农具 | 场景事件候选 | 连锁爆炸、动态路线等需另写规则 | 后续候选 |

“固定障碍”“可破坏场景物”“拾取物”“区域效果”使用不同组件，避免把所有互动塞进一个道具脚本。玉米初拟每 15 秒在空闲刷新点生成，回复 25 点生命；最终由试玩决定。

## 7. 首个完整原型：1v1 人机积分战

以下是默认验证规则，未代表正式发布模式：

- 1 名玩家对 1 个机器人，双方均为鸡；只有一张小农场地图。
- 倒计时 3 秒开局；一局最多 120 秒；先达到 5 次击败者胜出。
- 击败后 3 秒重生，重生后保护 1 秒；主动攻击或释放技能会提前结束保护。
- 有效击败归最后一次造成致命伤害的攻击者。M2 的场景不造成伤害，自身重置不计分。
- 时间到时分数高者胜；同分显示平局，不加时。比赛结束后当帧后续伤害和计分请求不再生效。
- 重生点先检查是否被占用，优先选离敌人较远的可用出生点，避免直接出生在对手脚下。
- 结算显示胜负、双方击败数和“再来一局”；重开时清空弹体、效果、冷却、地图破坏与道具状态。

机器人只需能追击、绕过简单围栏、在射程内攻击、受伤时偶尔退向玉米；遵守与玩家相同的冷却、射程、遮挡和可见性约束。首次实现可先不做主动撤退。

## 8. 后续模式与内容边界

在 1v1 和联网基础通过后，建议先验证 2–4 人农场乱斗。是否改为 2v2／3v3、争夺饲料或占点，等首轮试玩后再决定。团队战会增加队伍识别、复活、地图与匹配要求，不在此时承诺。

首个原型暂不安排：装备／出装、兵线、防御塔、排位赛、好友、公会、抽卡、通行证、商城、付费解锁、复杂养成、地图编辑器和大规模匹配。先验证走位与动物能力的组合，再选最有价值的扩展。

## 9. 试玩要回答的问题

1. 新玩家能否在 30 秒内理解移动、普攻和技能？
2. 能否一边移动一边稳定点按，且不因 UI 误触丢失移动？
3. 点按辅助瞄准是否可预测，是否经常打向不想攻击的目标？
4. 能否从画面看清“谁在前面、哪里不能走、为什么没打中”？
5. 干草堆与玉米是否改变走位，而不是只起装饰作用？
6. 输掉一局后，玩家是否愿意立刻重开，能否说出一次自己想改进的操作？

先记录 3–5 名试玩者的观察和具体问题，这只是方向验证，不据此宣称数值平衡或留存达标。

## 10. 后续细化模板

动物卡：名称／定位 → 普攻范围与节奏 → 主动技能与释放方式 → 对手如何反制 → 数值起点 → 所需动画与音效 → 训练场验收案例。

道具卡：类别 → 触发条件 → 对谁生效 → 持续／刷新／消耗 → 是否阻挡移动与弹体 → 与动物技能的互动 → 联网由谁判定。

模式卡：人数／队伍 → 胜负目标 → 时长 → 计分归属 → 死亡与复活 → 平局／掉线 → 地图布局 → 完整重开要求。
