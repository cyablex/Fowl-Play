# 设计决策与待决问题

更新日期：2026-10-19。这里区分用户已经确认的要求与为了推进工作采用的建议，避免将策划草案当成最终决定。

## 已确认

| 编号 | 决策 | 依据与影响 |
| --- | --- | --- |
| D01 | 引擎使用 Godot | 用户指定；完整版本在创建工程时锁定 |
| D02 | 纯 2D 角色和场景模拟 2.5D 纵深 | 用户明确选择；使用脚底碰撞与 Y 排序，不采用 3D 场景路线 |
| D03 | 俯视动物对战，场景以农场等环境为主题 | 用户描述；以走位、差异化攻击和场景互动构成玩法 |
| D04 | 左侧摇杆移动、右侧点按技能 | 用户指定；移动与释放必须支持多指同时操作 |
| D05 | 猪、马、鸡等动物有独特普攻和技能 | 用户指定动物方向；具体技能尚未确认 |
| D06 | 目标在 TapTap 发布 | 用户指定；从早期验证 Android 导出与平台接入路线 |
| D07 | 先形成框架与实现流程，再细化开发 | 本轮工作范围；当前不创建可玩工程或宣称功能完成 |
| D08 | 项目对接同名 GitHub 仓库 | 本地 origin 为 cyablex/Fowl-Play，已经核对远端 main |

## 建议采用的默认方案

| 编号 | 默认建议 | 原因 | 何时重新检查 |
| --- | --- | --- | --- |
| P01 | Android 横屏优先，Windows 键鼠辅助开发 | 与虚拟摇杆操作匹配，尽早验证真机 | M0 |
| P02 | Godot 4.x 稳定版、GDScript、Compatibility | 减少早期语言、渲染与移动设备适配变量 | M0 真机导出后 |
| P03 | 首个完整原型为鸡对鸡 1v1 人机 | 同时缩小美术、AI 与战斗变量 | M2 试玩后 |
| P04 | 每只动物先一种普攻、一个主动技能 | 先验证动物定位，控制按钮数量 | M2–M4 |
| P05 | 点按辅助瞄准，拖拽定向释放后置 | 优先满足点按需求，再根据试玩增加精确操作 | M1–M2 |
| P06 | 120 秒、先 5 分获胜、3 秒复活 | 让短局具有明确终点，便于多次验证 | M2 |
| P07 | 在线对战采用独立服务器权威判定 | 统一伤害与胜负，便于后续公开竞技 | M3 技术验证 |
| P08 | M2 后验证双客户端，再扩充三动物 | 尽早暴露同步问题 | M3 |

这些建议是可修改的工作基线，不代表用户已经确认所有细节。需要变动时更新此表及依赖文档，再推进相应实现。

## 后续细化顺序

| 优先级 | 待决定的问题 | 当前处理 |
| --- | --- | --- |
| 开工前 | 手绘卡通／像素风、目标手机、Godot 版本 | 用简单占位图起步，M0 记录实际选择 |
| 开工前 | 是否接受 Android 横屏和 1v1 人机原型 | 按默认方案规划，开始实现前写入版本基线 |
| 手感验证后 | 是否需要拖拽瞄准、按住连发或第二技能 | M1–M2 试玩后决定，避免一次增加全部控制方式 |
| 原型完成后 | 正式人数、个人混战或团队战、胜负目标 | M4 前确定；目前只保证 1v1 原型可定义清楚 |
| 联网验证前 | 可接受服务器预算与首批测试人数 | M3 测量资源后再定规模 |
| 平台测试前 | 发布主体、测试形式、商业化、接入范围 | 参照 TapTap 当前后台和官方资料核对 |
| 排期前 | 团队人数、Godot 经验、每天可投入时间 | 目前使用里程碑，不承诺日历工期 |

## 变更规则

需求变更先写“为什么改、影响哪些场景／数据／验收”，再修改任务。已经实现的行为以实际版本和验收结果为准，草案里未实现的内容不进入版本宣传。
