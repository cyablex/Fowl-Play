# TapTap 发布与 Android 接入准备

目标是让研发路径能够接上实际测试与发布。当前尚未创建 TapTap 游戏、申请资质、接入 SDK 或生成游戏安装包。本文件是准备清单，核对日期：2026-10-19。

## 1. 先区分几个不同目标

| 目标 | 项目需要的产物 | 安排 |
| --- | --- | --- |
| 本地开发试玩 | Godot 可运行工程、调试包、实际手机 | M0–M2 |
| 创建商店页面／预约 | 开发者身份、介绍、图标与展示素材 | 有可靠展示内容后准备 |
| 平台提供测试包下载 | 对应测试设置、审核资料和可用安装包 | M5–M6 |
| 正式上线 | 对应上线形式的资质、平台接入、审核与运营准备 | 满足条件后安排 |

“能导出 APK”“有商店页面”“可公开测试”“正式上线”分别验收，不能用其中一项替代其他阶段。

## 2. 平台要求核对

TapTap 当前快速入门说明对“联网／不联网、是否内购”区分所需材料；联网下载涉及 ICP 备案，提供测试或下载涉及防沉迷与隐私相关要求；正式上线与开放试玩的条件也有区别，不能把“无内购”理解为“可以直接正式上线”。具体按计划测试／上线形式与开发者后台核对。[TapTap 开发者快速入门](https://developer.taptap.cn/docs/store/standardies-operation/)

创建页面、上传包、提交审核和开测试是不同操作；应用包名应提前规划并与上传包及服务配置一致。[新建和管理游戏](https://developer.taptap.cn/docs/store/release/publish/create-game/)

因此，在 M0 就列出发布主体、联网性质、计划收费方式和预期测试形式；在 M5 前核实对应材料与接入路径。研发里程碑达到不等于平台审核已通过。

## 3. Android 技术路线

1. M0：锁定 Godot 与导出模板，按官方导出说明配置所需 Android 工具链，安装空包。
2. M1：在实际手机测试横屏、安全区、双指操作、返回键、切后台和分辨率。
3. M2：安装完整人机原型，验证十局重开、发热与内存变化，记录设备型号及构建号。
4. M3：联网构建启用必需网络权限，在两个实际客户端上测试连接与掉线。
5. M5：构建接入平台能力的包，验证原生回调、启动顺序、票据和异常返回。
6. M6：固定包名与发布签名，递增版本号，验证覆盖安装、启动、退出与旧版本处理。

Android 导出环境与版本要求以实际使用的 Godot 版本说明为准，不提前写死未经验证的 SDK／JDK 组合。[Godot Android 导出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html)

## 4. Godot 与平台服务的连接点

战斗系统不直接调用 TapTap SDK。在平台适配层提供调用入口，只有选定实际服务后才细化接口与实现。

- 登录：获得平台身份所需票据，交给自己的后端验证；客户端展示名不能充当身份凭证。
- 防沉迷等必需能力：明确实际选用的接入方式与流程，包括受限、取消、失败和恢复时的行为。
- 测试资格／更新等服务：根据本次测试形式选配，不把所有 SDK 功能一次性引入。
- 支付：尚未决定商业化，原型不接支付；确定需求后单独规划订单与服务端验证。

先核实所选 TapTap SDK、Godot 版本、Android 构建与插件路线的兼容性；若需要原生桥接，做一个只包含调用与回调的小工程真机验证，再集成游戏。此处没有假定现成 Godot 插件必然可用。[TapTap SDK 概览](https://developer.taptap.cn/docs/sdk/)、[Godot Android 插件](https://docs.godotengine.org/en/stable/tutorials/platform/android/android_plugin.html)

平台账号服务、房间服务与战斗同步是不同系统。接入 TapTap 登录不等于已经完成真人匹配或联网对战。

## 5. 公开测试前的实际产物

- [ ] 明确开发者／发布主体、计划测试范围、所选形式及对应材料。
- [ ] 有可用的签名安装包，版本号、包名、权限说明与后台一致。
- [ ] 实际平台流程可走通，并能演示必需接入行为。
- [ ] 联网版本在外网完成创建／加入／游玩／结算，服务器与费用可支撑预期规模。
- [ ] 有真实截图、实机视频、玩法说明、反馈入口和已知问题。
- [ ] 隐私说明与实际 SDK／权限行为一致；外部素材来源和使用权限可追溯。
- [ ] 发布签名与服务器凭据保存在仓库外，具备受控备份。
- [ ] 测试结果与构建版本可对应，发生问题可停止放量并重新发包。

首版平台页面宣传只描述已实现行为，例如尚无人机以外的玩法时，不宣传实时匹配或四人对战。
